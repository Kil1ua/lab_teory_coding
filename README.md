# Сжатие данных без потерь: LSTM + контекстная модель + арифметическое кодирование

Учебный проект по теории информации и кодированию. Реализован алгоритм **сжатия без потерь**, в котором вероятности следующих байтов оцениваются совместно онлайн-обучаемой **LSTM** и **PPM-подобной контекстной моделью**. Итоговое распределение передаётся 32-битному арифметическому кодеру.

Модификация исходного LSTM-подхода состоит в использовании статистики контекстов переменной длины, escape-вероятностей, исключений ранее учтённых символов и **адаптивного смешивания** двух предсказателей.

## Результат

На файле `enwik5` размером **100 000 байт** получен следующий результат:

| Показатель | Исходная версия (по заданию) | Предложенная версия |
|---|---:|---:|
| Исходный размер | 100 000 байт | 100 000 байт |
| Размер архива | 33 326 байт | ≈ 29 326 байт* |
| Коэффициент сжатия | ≈ 3,0007 | **≈ 3,41** |
| Бит на исходный байт (BPC) | ≈ 2,6661 | **≈ 2,3460** |
| Полное время | 156 с (из задания) | **≈ 55 с - AMD Ryzen 7 8845HS; ≈ 95 с - AMD Ryzen 7 2700X** |
| Восстановление без потерь | Требование задания | Проверяется сравнением MD5 |

\* Размер архива улучшенной версии вычислен по округлённому коэффициенту 3,41; точное значение следует смотреть в воспроизведённом запуске и опубликованном `results.json`.

**Прирост коэффициента сжатия — примерно 13,64%** относительно исходных размеров архива, что превышает требуемые 10%.

**О времени:** полное время выполнения зависит от процессора. Для предложенной модели получено **около 45 с на AMD Ryzen 7 8845HS** и **около 95 с на AMD Ryzen 7 2700X**. Показатель **156 с** взят из задания для исходной версии и **не является прямым сравнением производительности на одном устройстве**. Для корректного сравнения быстродействия обе версии нужно запускать на одинаковом оборудовании. Время в `results.json` включает кодирование, декодирование и проверку восстановленного файла.

## Структура репозитория

```text
.
├── main.py                         # LSTM + PPM-подобная модель + кодирование/декодирование
├── ArithmeticCoder.py              # реализация арифметического кодирования
├── requirements.txt                # зависимости Python
├── results.json                    # результаты запуска
├── README.md
└── data/
    ├── enwik5                      # исходный файл (100 000 байт)
    ├── enwik5_compressed.dat       # результат сжатия
    └── enwik5_decompressed.dat     # восстановленный файл
```

`main.py` использует `path_to_file = "data/enwik5"`, поэтому создаёт `data/enwik5_compressed.dat` и `data/enwik5_decompressed.dat` **внутри каталога `data/`**. Эти файлы могут уже присутствовать в репозитории; очередной запуск их перезапишет. Данный README описывает алгоритм под именем `main.py`.

## Что делает `main.py`

При значении `mode = "both"` (установлено в файле по умолчанию):

1. Читает `data/enwik5` как байтовую последовательность и формирует алфавит встречавшихся байтов.
2. Инициализирует LSTM и контекстную модель с фиксированным начальным состоянием.
3. Для каждого следующего символа вычисляет распределение вероятностей LSTM и PPM-подобной модели.
4. Смешивает предсказания с учётом накопленной статистики контекстов и кодирует символ арифметическим кодером.
5. После обработки символов обновляет статистические счётчики и обучаемые веса LSTM.
6. Повторяет те же действия при декодировании, восстанавливая `data/enwik5_decompressed.dat`.
7. Проверяет совпадение MD5 исходного и восстановленного файлов; сохраняет `results.json`.

Ключевая формула смешивания:

$$
P_{\mathrm{mix},t}(a)=(1-w_t)P_{\mathrm{LSTM},t}(a)+w_tP_{\mathrm{ctx},t}(a),
\qquad w_t=w_{\max}\gamma_t.
$$

Здесь $w_{\max}=0.6$ - **заранее выбранный максимальный вес**, а $\gamma_t\in[0,1]$ — доверие к контекстной модели, рассчитываемое по накопленным частотам. LSTM обучается на собственной отрицательной логарифмической вероятности правильных символов, а арифметический кодер использует **смешанное** распределение.

Контекстный алгоритм **PPM-подобный**, но **не является буквальной реализацией классического PPM-D**: формулы распределения массы между известными символами и переходами к коротким контекстам имеют небольшую модификацию.

## Параметры итоговой конфигурации

```python
params = {
    "seq_length": 4,
    "num_layers": 1,
    "rnn_units": 768,
    "embedding_size": 150,
    "start_learning_rate": 0.005,
    "end_learning_rate": 0.0001,
    "batch_size": 128,
    "ng_order": 5,
    "ng_weight": 0.6,
}

SEED = 1234
FREQ_SCALE = 16000000
```

Для контекстной модели используется `conf_scale=20.0` (значение по умолчанию в `PPMNgramModel`). Веса LSTM и статистика контекстов обновляются автоматически; приведённые гиперпараметры зафиксированы перед запуском.

## Файлы результатов

После успешного запуска:

- `data/enwik5_compressed.dat` - сжатое представление.
- `data/enwik5_decompressed.dat` - восстановленные байты, которые должны совпадать с исходными.
- `results.json` - краткая статистика выполнения.

Формат `results.json` текущей реализации:

```json
{
  "success": true,
  "compression_ratio": 3.41,
  "time_spent": 55.6,
  "peak_gpu_memory_gb": null
}
```

Это **пример структуры** с округлённым временем для AMD Ryzen 7 8845HS (на AMD Ryzen 7 2700X оно составляет около 95 с). Точные значения необходимо брать из фактически созданного файла. При ошибке добавляется поле `error` и `success` становится `false`.

```bash
# Linux / macOS
sha256sum data/enwik5 data/enwik5_decompressed.dat
```

```bash
# Windows PowerShell
Get-FileHash data/enwik5 -Algorithm SHA256
Get-FileHash data/enwik5_decompressed.dat -Algorithm SHA256
```

Совпадение хешей подтверждает побайтовое соответствие с высокой криптографической надёжностью; сама программа проверяет MD5.

## Воспроизводимость и ограничения

- Для декодирования необходимо использовать **те же гиперпараметры, алгоритм и совместимую вычислительную среду**, что при кодировании. Обученные веса не сохраняются в архиве: они воспроизводятся в ходе симметричного онлайн-обучения.
- Параметры сети и контекстной модели **не включены в заголовок архива**; они определяются кодом.
- Результат времени зависит от CPU, версий библиотек и системной нагрузки. Коэффициент сжатия следует сравнивать на одном и том же файле и с зафиксированной конфигурацией.
- Скрипт рассчитан прежде всего на демонстрацию метода на `enwik5`; результат на других типах файлов не гарантирован.
